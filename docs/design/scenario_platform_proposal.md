# 제안서 — 시나리오가 계속 이어지는 게임 만들기

> 상태: 제안 (2026-10-13). 결정이 필요한 항목은 8절에 모았다.
> 전제: "윤 대감 댁의 마지막 밤"이 첫 시나리오이고, 이후 시나리오는 사용자가 계속 만든다. 플레이어는 새 시나리오를 계속 만나고, 지난 시나리오도 다시 즐길 수 있어야 한다.

## 1. 문제: 머더미스터리는 원래 한 번 하면 끝이다

범인과 진상을 알면 같은 시나리오의 재미는 대부분 사라진다(보드게임판도 "1회용"이 기본). 그래서 "재활용"을 세 갈래로 나눠 접근한다.

| 갈래 | 뜻 | 주 대상 |
|---|---|---|
| ① 다시 플레이 | 이미 해 본 시나리오를 다시 즐길 이유 만들기 | 플레이어 |
| ② 자산 재활용 | 맵·인물·규칙을 다음 시나리오에 그대로 쓰기 | 제작자(사용자) |
| ③ 계속 공급 | 새 시나리오가 꾸준히 들어오고 고르기 쉬운 구조 | 둘 다 |

## 2. ① 다시 플레이하는 방법 (추천 순)

### A. 경험자는 "진행자·조력자"로 (추천, 비용 작음)
- 이미 해 본 사람이 방에 들어오면 **도 검률 역(진행자)**이나 **관전자**로 참여한다.
  - 진행자 모드: 지금 규칙 기반으로 답하는 도 검률의 답변을 사람이 고르거나 덧붙인다. 공지·단계 진행도 진행자가 한다.
  - 관전자 모드: 모든 정보를 보지만 말하지 못한다(또는 끝난 뒤 복기에서만 말함).
- 효과: 친구를 데려와 처음 하는 사람에게 시나리오를 "보여 주는" 2회차. 보드게임 머더미스터리에서 가장 흔한 재사용 방식이다.

### B. 진상 변주(케이스 변형) (추천, 시나리오당 작업 필요)
- 같은 집·같은 인물·같은 첫 상황에서 **진상만 다른 변주**를 2~3개 둔다. 방을 만들 때 무작위 또는 호스트가 고른다(플레이어에게는 숨김).
- 바뀌는 것: 범인, 쓰인 도구, 핵심 단서 2~4개, 일부 시나리오북 문단, 엔딩.
- 그대로인 것: 맵, 인물 관계, 사건 전 상황, 대부분의 단서.
- 데이터: 단서·팩트·시나리오북에 `variant` 표시 → 공통 + 변주별 덮어쓰기.
- 주의: 변주끼리 앞뒤가 맞아야 한다. 검증기가 변주마다 "범인 특정 경로"를 따로 확인해야 한다 (balance_review의 방식을 변주마다 반복).

### C. 무작위 요소 (보조)
- 진상은 그대로 두고 판을 흔든다: 같은 의미의 단서가 다른 장소에 놓임, 개인 목표 카드 무작위, 도 검률 답변 문장 풀(이미 있음), 진행 중 사건 카드(비가 와서 마당 발자국이 지워짐, 이웃의 소문 등).
- 진상을 아는 사람에게는 재미가 크지 않으므로 A·B와 함께 쓴다.

### D. 연작(시즌)
- 같은 집·같은 가문의 **다음 사건**. 첫 시나리오에서 잠가 둔 사당이 후속 시나리오용으로 예약돼 있다(map_layout).
- 지난 편의 엔딩(A/B/C)을 기록해 두고, 다음 편 도입이 달라진다("지난번엔 재하가 붙잡혔다…").
- 새 시나리오를 "처음 하는 사람"도 즐길 수 있게 도입부에 요약을 넣는다.

### E. 복기(리플레이) 모드
- 판이 끝나면 **실제 타임라인을 재생**한다: 그날 밤 누가 몇 시에 어디 있었는지 인물 모형이 맵 위를 움직이고, 플레이어들이 조사 시간에 다닌 경로도 겹쳐 보여 준다.
- 다시 플레이하지 않아도 "한 번 더 보고 싶은" 요소가 되고, 진행자 모드(A)의 교재가 된다.

## 3. 스포일러 관리 (A·B를 쓰려면 필요)
- 플레이 기록: 플레이어마다 "한 시나리오·변주"를 저장한다 (Unity Cloud Save, 익명 계정에 연결).
- 방 들어갈 때: 해 본 시나리오면 안내하고, 기본은 진행자·관전자로만 앉게 한다. 방 설정에서 "경험자도 인물 선택 허용"을 켤 수 있다(변주가 있을 때).
- 시나리오 선택 화면에 "해 봄" 표시와 변주 진행도(예: 1/3)를 보여 준다.

## 4. ② 자산 재활용: 시나리오 패키지 구조 (제안)

지금도 규칙 엔진은 데이터로 움직인다(`Resources/Data/*.json`: 단서·인물·팩트·도 검률 답변·진행 단계·엔딩). 이것을 **시나리오 단위 패키지**로 묶고, 맵과 인물은 따로 재사용 목록으로 뺀다.

```
Scenarios/<scenario-id>/
  scenario.json        # 이름, 한 줄 소개(스포일러 없음), 인원, 시간, 난이도, 태그, 사용할 맵 id, 버전, 제작자
  data/                # 지금의 clues, characters, facts, npc_dialogue, flow, endings (+ variants/)
  books/               # 인물별 시나리오북 (게임 안에서 열람)
  staging.json         # 이 맵 위의 배치: 조사 지점·소품·스폰·토론 장소·NPC 자리·금지 구역
  cast.json            # 인물 id → 배우(외형) id, 키·체격
  art/                 # 표지 그림, 인물 초상
Maps/<map-id>/          # 장면, 몸 프로필(PlayerBodyProfile), 맵 자체의 금지 구역 — 여러 시나리오가 공유
Actors/<actor-id>/      # 리깅된 인물 외형 — 여러 시나리오가 공유 (옷만 바꿔 다른 인물로)
```

- 코드 변경: `GameData.Load(scenarioId)`, 방(세션) 속성에 `scenarioId@version`, `NetGame`이 그 시나리오를 불러옴. 지금 `KhsManorBuilder`에 표로 박혀 있는 배치(조사 지점·소품·NPC)를 `staging.json`으로 옮긴다.
- 새 시나리오 만들 때의 재사용: 같은 맵(김명관 고택)에 다른 방을 사건 장소로 쓰고, 배우 6명의 옷만 바꾸면 인물 준비가 하루 안에 끝난다. 규칙(단계·밀담·투표·점수)은 `flow.json`으로 조절.
- 인물·배치 규칙은 `character_staging.md`를 그대로 따른다.

## 5. ③ 계속 공급: 제작 도구와 배포

### 제작 흐름 (사용자 기준)
1. `Tools > 시나리오 > 새 시나리오`(템플릿 복제) → 이름·인원·맵 선택
2. 문서 작업(지금처럼 docs/에서 설정집·타임라인·시나리오북) → 데이터 JSON 채우기
3. 배치: 맵을 열고 조사 지점·소품을 끌어다 놓기 → `staging.json` 저장
4. 검증 버튼 하나: 데이터 검증(DataValidator), 걸어서 도달 검증, 범인 특정 경로(변주별), **스포일러 누출 검사**(공용 문구·표지 소개에 범인 이름이 나오는지)
5. 혼자 미리보기(1~5 인물 전환, 이미 있음) → 지인 테스트(playtest_guide)

### 배포
- 1단계: 시나리오를 게임 빌드에 포함(지금 방식). 새 시나리오 = 새 빌드.
- 2단계: **원격 배포** — 시나리오 패키지를 Addressables로 묶어 Unity Cloud Content Delivery에 올리면, 게임을 다시 깔지 않고 시나리오 목록이 늘어난다. 호스트와 참가자의 시나리오 버전이 같아야 방에 들어갈 수 있게 한다.
- 3단계(먼 미래): 다른 사람이 만든 시나리오 올리기 — 검수·신고·평점이 필요해 지금은 범위 밖.

## 6. 화면 구성 (P7에서 구현)
- 진입 화면 → 메인 메뉴(시나리오 고르기 / 코드로 참가 / 혼자 연습 / 설정)
- 시나리오 선택: 봉투·사건첩 모양 카드, 인원·시간·난이도, "해 봄" 표시, 준비 중인 시나리오는 봉인된 카드
- 방 만들기: 공개/비공개, 음성 사용, (변주가 있으면) 변주 무작위/지정, 경험자 처리 방식
- 대기실: 큰 방 코드, 인물 초상 카드 5장, 준비 표시, 호스트 시작
- 이번 구현에서는 패키지 구조 중 `scenario.json`(목록·카드에 필요한 정보)만 먼저 만든다.

## 7. 추천 로드맵

| 순서 | 내용 | 효과 |
|---|---|---|
| 1 | 화면(6절) + `scenario.json` 목록 | 시나리오가 여러 개인 게임의 뼈대 |
| 2 | 패키지 구조로 이전(데이터·배치 분리) | 두 번째 시나리오 제작 준비 완료 |
| 3 | 진행자·관전자 모드(A) + 플레이 기록 | 경험자도 함께 놀 수 있음 |
| 4 | 두 번째 시나리오(같은 집, 다른 사건 또는 연작 D) | 재활용 구조 검증 |
| 5 | 변주(B)를 첫 시나리오에 1개 추가 | 다시 플레이 가치 |
| 6 | 복기 모드(E) | 끝난 뒤의 재미, 진행자 교재 |
| 7 | 원격 배포 | 빌드 없이 시나리오 추가 |

## 8. 결정이 필요한 것

- [ ] 게임(플랫폼) 이름 — 지금 화면에는 가제를 쓴다
- [ ] 2회차 기본 방침: 경험자를 진행자·관전자로만 받을지, 변주가 있으면 인물로도 받을지
- [ ] 첫 시나리오에 변주를 넣을지(진상의 감정선이 강해서 변주 설계가 어렵다 — 연작(D)이 더 맞을 수 있음)
- [ ] 두 번째 시나리오 방향: 같은 집의 후속(연작) / 같은 집의 독립 사건 / 다른 맵
- [ ] 진행자 모드에서 도 검률을 LLM으로 보조할지(이전 결정: 지금은 규칙 기반)
