# 인물 움직임·배치 기준 (모든 시나리오 공통)

> 첫 시나리오(윤 대감 댁)를 만들며 정한 규칙과 겪은 문제를 정리했다. 새 시나리오의 맵·인물·배치를 만들 때 이 문서를 체크리스트로 쓴다.
> 코드 위치는 `Assets/_Project/Scripts/` 기준.

## 1. 플레이어 몸 (1인칭)

| 항목 | 기본(블록아웃) | 한옥 스캔 맵 | 이유 |
|---|---|---|---|
| 키 | 1.70 m | **1.45 m** | 한옥 문 높이가 문지방 위 1.74 m. 키 + 계단 + 여유가 문 높이보다 낮아야 문을 지난다 |
| 반지름 | 0.30 m | 0.25 m | 좁은 툇마루·문짝 사이 |
| 계단(stepOffset) | 0.35 m | **0.15 m** | 문지방만 넘는 정도. 크게 하면 낮은 문 위턱에 걸린다 |
| 보조 오르기(StepAssist) | — | **0.62 m** | 기단·섬돌(0.6 m)을 오른다. 앞이 막히고 위에 머리 공간이 있을 때만 몸을 올림. 얇은 문지방도 찾도록 가까운 곳부터 잰다. 위가 낮으면 숙여서 오른다 |
| 숙이기(Duck) | — | **1.1 m** | 머리 높이에 뭔가 걸리면 자동으로 몸을 줄이고, 자리가 나면 일어선다. 눈높이도 같이 내려간다. NavMesh 검증의 몸 높이도 1.1 m |
| 눈높이 | 1.55 m | 1.33 m | 앉으면 62 % |
| 점프 | 0.45 m | 0.45 m | 돌·문턱만. **보조 오르기보다 낮게** 유지해야 막아 둔 구역이 새로 뚫리지 않는다 |

- 맵마다 `PlayerBodyProfile`을 씬에 둔다 (`Level/PlayerBodyProfile.cs`). 없으면 기본값.
- 점프 계산은 프레임 속도와 무관해야 한다 (`FirstPersonController`: 속도 평균 적분). 느린 프레임에서 1.6 m까지 뛰던 버그가 있었다.
- 막을 곳(출입 금지 구역)은 **3 m 높이 보이지 않는 벽**으로 막는다. 담 높이에 기대지 않는다.

## 2. 맵에 인물을 놓는 규칙

### 스폰·토론·NPC
- **스폰 5곳**은 토론 장소 둘레 반지름 3 m 원 위 (`GameplayMarker` PlayerSpawn). 흙마당 등 평평한 곳.
- **토론 장소**는 모두가 서로 보이는 마당 한가운데. NPC가 보이는 방향이어야 한다.
- **진행 NPC**는 마당에서 보이는 자리(툇마루 앞쪽)에 마당을 향해 세운다. 닫힌 문 뒤(대청 안쪽)에 두면 안 보인다 — 첫 배치에서 실제로 그랬다.
- NPC 높이는 바닥을 레이로 재서 맞춘다 (`KhsManorBuilder.FloorY`). 발 접지는 런타임이 마저 맞춘다(4절).

### 조사 지점
- 지점은 **바닥 높이 + 소품 높이**에 둔다. 좌표만 정하지 말고 생성기에서 바닥을 레이로 잰다.
- 모든 지점은 토론 장소에서 **걸어서** 닿아야 한다 → 6절 검증 두 가지를 반드시 통과.
- 지점마다 실제 물건(소품)을 둔다. 소품은 바닥(또는 받침 소품 위)에 붙여 놓는다 (`KhsManorBuilder.Props`, `PropOn`).
- 현재 소품에는 충돌체가 없다(몸이 통과). 충돌체를 넣으면 지점 접근 검증을 다시 돌린다.

### 스캔 맵의 함정
- 스캔 집은 땅이 울퉁불퉁한데 게임 마당은 평평하다 → 돌·항아리가 뜬다. `SettleFloatingPieces`가 내려앉힌다 (겹친 조각은 묶어서 함께 이동, 돌 테두리는 묶지 않음).
- 스캔의 충돌체는 메시 참조가 빠져 있을 수 있다 → 생성기가 다시 만든다.
- 스캔에 **벽이 빠진 칸**이 있을 수 있다 (사랑채 서재 북벽 등) → 한지 칸막이로 채운다. 시나리오가 "벽 너머로 들렸다", "문틈으로 봤다"에 기대면 꼭 확인.
- 방 문짝은 근접 시 열린다 (`ProximityDoor`, 1.3 m). 닫아 둘 문은 좌표로 정한다 (`KhsManorBuilder.LockedGates`).
- 스캔 집이 땅보다 뜨면 집을 내리지 말고 **땅을 받침 밑으로 올린다** (`FindFootings`/`BuildGround`). 땅을 고친 뒤에는 막아 둔 구역이 경사로로 새로 뚫리지 않는지 `VerifyWalkability`로 꼭 확인.
- 높은 마루방 문 앞에는 디딤돌이 있어야 들어간다 (`BuildDoorSteps`가 자동 배치). 새 맵은 `WalkabilityProbe.DoorMode`로 문 전부를 걸어 본다.

## 3. 인물 외형 (한복 의상 → 리깅 → 동작)

1. 의상: `CharacterOutfitBuilder` 표에 인물마다 조각을 고른다. **신분 고증** + **추리용 실루엣**(키·체격·갓 유무)을 같이 정한다. 키는 타임라인 문서의 목격 묘사와 맞춘다.
2. Mixamo 리깅: `Export Outfits for Mixamo` → mixamo.com 업로드 → With Skin.
   - **다리가 보여야** 자동 리깅이 된다. 바닥까지 오는 치마·단령은 실패한다.
   - 치마: 리깅용 파일에서는 빼고 속바지로 리깅 → 나중에 골반 뼈에 붙임(폭 1.15배), 치마 속 다리·신은 숨김.
   - 발목까지 오는 옷(흑단령)은 다리가 보이는 옷으로 바꾸는 게 낫다 (도 검률 → 동달이·전복).
3. 뼈에 붙이는 부품(리깅 후, 다시 올릴 필요 없음): 남자 상투 머리(머리 뼈), 얼굴(눈썹·코·입, 머리 뼈), 손(손 뼈), 치마(골반 뼈).
4. 동작 파일(Without Skin): `Idle.fbx`, `Walking.fbx`(In Place) 필수. `Sitting.fbx`, `Jump.fbx` 선택.
5. `Build Rigged Characters (Mixamo)` 한 번이면 위 전부 + 재질 복원 + 키 맞춤 + 고개 보정.

## 4. 런타임 자세 보정 (`CharacterAnimator`)

| 문제 | 해결 |
|---|---|
| 동작마다 발이 떠 있음 (신발 속 발목이 높게 잡힘) | 매 프레임 발 뼈를 바인드 자세의 발바닥 높이에 맞추고, 0.5초마다 실제 메시 최저점으로 오차 보정 |
| CharacterController 기준점이 땅보다 8 cm 위 | 발밑을 레이로 재서 그 높이를 땅으로 사용 |
| 점프 중 발이 땅으로 끌려감 | 땅에서 15 cm 이상 떨어지면 공중으로 보고 접지 끔 |
| 리깅마다 목이 젖혀짐 (긴 머리 등) | 서기 자세에서 인물들의 목 각도를 비교해 중앙값에서 크게 벗어난 인물만 보정 |
| 화면 밖에서 보정이 누적 | 애니메이터를 항상 갱신(AlwaysAnimate). 인원이 적어 부담 없음 |
| 걷기/서기 전환 | 실제 이동량으로 속도 계산 → 네트워크 몸·NPC 모두 동일 |

## 5. 네트워크

- 위치·방향: 소유자 권한 `NetworkTransform`. 점프는 위치로 그대로 보인다.
- 앉기: `NetPlayer`의 소유자 쓰기 `NetworkVariable<bool>`.
- 원격 몸은 `Resources/Characters/<인물 id>` 프리팹. 새 인물은 이 경로에 같은 id로 둔다.

## 6. 검증 (새 맵·새 배치마다 필수)

1. `KhsManorBuilder.VerifyWalkability` — NavMesh로 모든 지점·NPC·스폰 도달 + 금지 구역(바깥, 바깥마당, 사당) 새는 길 없음. 금지 구역 좌표는 생성기의 `Forbidden` 표에 시나리오마다 추가.
2. `WalkabilityProbe` (Play) — 플레이어와 같은 몸이 실제로 걸어서 모든 지점에 도착하는지.
3. 뜬 조각 검사 — 스캔 맵이면 생성 로그의 "settled N" 확인.
4. 2인 접속 — 원격 인물이 걷고·서고·앉는 모습, 발 접지, 고개 각도를 호스트 화면에서 촬영.
