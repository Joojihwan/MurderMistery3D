# 진행 NPC 도 검률 — 응답 규칙 명세

> 상태: 확정 (2026-10-11). AI(LLM) 연결 없이 규칙 기반 + 사전 작성 문장 풀에서 골라 답한다.

## 1. 역할

중인 출신 법률 관리(검률). 폭우로 하룻밤 묵게 된 외부인으로, 사건 현장(중문 안쪽)에 들어간 적이 없어 용의자가 아니다.
사또가 당도하기 전 초검 검안서를 올려야 한다는 명분으로 게임을 진행한다. 말투는 하오체.

담당 기능: 단계 진행 알림(시 단위: 묘시·진시·사시, [game_rules.md](game_rules.md) 2절), 공통 단서(검시 결과) 공개, 조사 허가와 행동 관리, 밀담 시간 관리, 1:1 질문 응답, 투표 주재, 엔딩 낭독.

단계 알림·검시 결과·엔딩은 고정 대본이며 이 문서의 질문 응답 규칙과는 별개다.

## 2. 중립 규칙

| # | 규칙 | 내용 |
|---|---|---|
| R1 | 거짓말 금지 | 어떤 문장도 사실과 다르면 안 된다. |
| R2 | 의견 금지 | 범인 지목·추리·해석을 하지 않는다. 사실만 말하며 여러 사실을 엮은 결론을 문장에 넣지 않는다. |
| R3 | 아는 만큼 답한다 | 답의 근거는 `공개 Fact ∪ 질문자 보유 Fact` 뿐이다. 질문자에 따라 답의 깊이는 달라질 수 있으나 서로 모순되지 않는다. 타인만 가진 Fact는 절대 말하지 않는다. |
| R4 | 거절은 구분 없이 | 범위 밖 질문에는 정보가 실제로 있든 없든 같은 거절 문장 풀에서 같은 방식으로 고른다. |
| R5 | 질문은 1:1 | 질문 응답은 다른 플레이어가 듣지 못하는 1:1 대화에서만 한다. 여럿 앞에서는 공개 Fact만 말한다. |
| R6 | 정보 이동 | 단서를 전체 공개하면 즉시 공개 Fact가 된다. 단서를 건네면 받은 사람의 보유 Fact에 추가된다(건넨 사람도 유지). 구두로 들은 내용은 이동하지 않는다. |
| R7 | 질문 횟수 | 조사 단계마다 1인당 2회. 같은 주제를 다시 물어도 1회 차감된다. 토론 단계에서는 1:1 질문을 받지 않는다. |
| R8 | 연출 중립 | 답변·거절 모두 같은 애니메이션, 같은 대기 시간, 같은 효과음을 쓴다. 표정·몸짓으로 정보가 새지 않게 한다. |

## 3. 질문 방식 (주제 선택형)

자유 입력 대신 주제를 고른다.

```
"무엇을 묻겠소?"
├─ 인물      : 윤 대감, 다섯 인물
├─ 장소      : 공개된 장소 + 질문자가 조사한 장소
├─ 증거물    : 질문자가 가진 단서 / 공개된 단서
└─ 사건 사실 : 사인, 발견 경위, 밤 사이 시각 등 공개 항목
```

- 주제 목록에는 질문자가 이미 아는 대상만 나타난다. 목록 자체로 정보가 새지 않는다.
- 일부 주제는 해당 Fact를 가진 사람에게만 열린다.

## 4. 답변 선택 알고리즘

```
입력: 질문자 P, 주제 T
1. T에 연결된 답변 항목(tier)들을 tier 높은 순으로 본다.
2. 항목의 required_facts가 모두 (공개 Fact ∪ P 보유 Fact)에 있으면 그 항목을 고른다.
3. 고를 항목이 없으면 거절 풀에서 문장을 고른다. (R4)
4. 고른 항목의 문장 변형 중 하나를 섞인 순서로 꺼낸다. (5절)
5. [도입구] + 본문 + [맺음구]로 조립해 출력하고, 답변을 P의 수첩에 기록한다.
6. P의 질문 횟수 1 차감.
```

같은 주제를 물어도 질문자가 가진 Fact에 따라 다른 tier가 선택되므로 답의 깊이가 달라진다(R3).

## 5. 문장 변형 규칙

- 한 항목의 모든 변형은 정확히 같은 Fact 집합을 전달한다. 더하거나 빼거나 뉘앙스를 바꾸지 않는다. 표현과 어순만 다르다.
- 선택 방식: 셔플 백. 항목·플레이어별로 변형 순서를 섞어 차례로 꺼내고, 다 쓰면 다시 섞는다. 직전에 쓴 문장은 다음 첫 문장이 되지 않게 한다.
- 최소 변형 수: 사실 답변 3개, 거절 5개, 도입구·맺음구 각 5개.
- 거절 풀은 하나만 둔다. 정보가 "없음"인 경우와 "타인 보유"인 경우를 구분하는 풀을 만들지 않는다(R4).
- 도입구·맺음구는 모든 답변·거절에서 같은 풀을 공유하며 의미 없는 말만 쓴다. 감정이나 평가가 담긴 말("흠, 수상하군")은 금지한다(R2, R8).

### 예시 (공개 Fact: 탕약 독 반응)

본문 변형:
1. 탕약 그릇에 은비녀를 넣었더니 검게 변했소. 독이 들어 있었다는 뜻이오.
2. 은비녀가 탕약에 닿자 검게 물들었소. 탕약에 독이 섞여 있었던 게요.
3. 검시해 보니, 탕약 그릇에 담근 은비녀가 검어졌소. 독이 든 탕약이었소.

거절 풀:
1. 그 일은 내가 그대에게 답할 수 있는 바가 아니오.
2. 그건 내 검안서에 적힌 바가 아니오.
3. 그 물음에는 내가 드릴 말이 없소.
4. 그대가 물을 수 있는 일이 아닌 듯하오.
5. 그 일에 대해선 일러줄 것이 없소.

도입구: "들어 보시오." / "그 일이라면," / "검안서에 따르면," / "음," / (없음)
맺음구: (없음) / "이상이오." / "그뿐이오." / "더 묻겠소?" / "참고하시오."

## 6. 수첩

- NPC에게 들은 답은 질문자 개인 수첩에 자동 기록된다. 다시 들으려고 질문을 소모할 필요가 없다.
- 수첩 기록은 보유 Fact를 늘리지 않는다. NPC 답은 이미 아는 Fact나 공개 Fact만 담기 때문이다.

## 7. 데이터 구조

```jsonc
// Fact
{ "id": "F_POISON_SILVER", "scope": "public",            // public | character | clue
  "holders": [],                                          // scope=character일 때 처음 아는 인물
  "clue_id": null,                                        // scope=clue일 때 연결 단서
  "note": "탕약 은비녀 독 반응" }

// 답변 항목
{ "topic_id": "T_TANGYAK", "tier": 0,
  "required_facts": ["F_POISON_SILVER"],
  "conveys_facts": ["F_POISON_SILVER"],
  "variants": ["...", "...", "..."] }

// 공용 풀
{ "refusals": ["..."], "openers": ["..."], "closers": ["..."] }
```

## 8. 작성 검증 체크리스트 (데이터 검증 툴로 자동화 예정)

- [ ] 모든 항목에서 `conveys_facts ⊆ required_facts ∪ 공개 Fact` (NPC가 새 정보를 주지 않음)
- [ ] 같은 주제의 상위 tier는 하위 tier 정보와 모순되지 않음
- [ ] 변형 수 최소 기준 충족
- [ ] 변형 간 전달 Fact 동일 (수동 검토)
- [ ] 도입구·맺음구·거절 풀에 평가/감정 표현 없음
- [ ] 범인을 특정하거나 추리를 담은 문장 없음
